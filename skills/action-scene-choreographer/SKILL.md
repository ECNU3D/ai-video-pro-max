# 动作戏导演编排器

## Overview

把已经确定剧情目标的动作场次，进一步整理成一份“这一场为什么开打、怎么升级、怎么反转、怎么收”的导演编排文档。

核心原则：先把动作戏的戏剧任务、攻防逻辑、强弱变化和高潮落点设计清楚，再下放到平台提示词。默认输出的是动作戏导演编排，不是最终平台 prompt。

生成前先阅读：
- `references/action-template.md`：固定输出结构与表格
- `references/action-checklist.md`：动作戏编排审核清单

## Scope Decision

优先按“一个动作段落”处理，不要整集一次性混做。

1. 单场动作戏：
默认最佳输入单位，适合完整编排。

2. 一段连续动作流程：
例如“开端对峙 + 近身交锋 + 追逐 + 大招对轰”，可以放在同一份文档里。

3. 整集：
不要整集都写进一份动作编排。先拆出真正需要精细设计的动作段落。

如果用户只给了一个模糊概念，比如“打一架，要酷一点”，没有人物关系、胜负方向、场景条件、能力设定等基本信息，先补“动作戏设计所需关键信息”，不要假装已经可以精细编排。

## Workflow Overview

按下面顺序执行：

1. 明确动作戏的戏剧任务与胜负方向
2. 判断动作类型与写实度
3. 选择合适的动作模板组合
4. 设计强弱转换与攻防节拍
5. 设计环境、道具、位移与特效逻辑
6. 规划高潮、高潮尾戏与收尾
7. 输出供人审阅的动作戏导演编排文档

## Preferred Inputs

理想输入优先级如下：

1. `storyboard-blueprint` 输出的导演分镜蓝图
2. 单场戏剧本 / 文字分镜 / 动作段落需求
3. `continuity-blocking-planner` 输出的空间与走位规划
4. 角色能力设定、武器设定、场景设定、参考图

如果同时拿到多个来源，以导演蓝图和剧情任务为主，不要让平台分镜写法反过来支配动作设计。

## Step 1: Define The Dramatic Mission

先回答这场动作戏为什么存在。至少写清：

- 谁和谁打 / 追 / 对峙
- 当前关系是什么：敌对、试探、报复、营救、逃生、阻截、决胜
- 谁更强、谁更弱
- 最终谁赢、谁输，或至少谁暂时占上风
- 这一场结束后，剧情状态会发生什么变化

没有胜负方向的动作戏，通常只剩“热闹”而缺少推动力。

## Step 2: Choose Action Type And Reality Level

先给动作戏定类型，再决定动作语言：

- 对峙戏：强调压迫感、威慑、气氛累积
- 近身攻防戏：强调攻防因果、节拍、见招拆招
- 群战 / 清场戏：强调主次目标、局部胜负与空间压力
- 追逐戏：强调方向、障碍、距离变化、强弱反转
- 大招 / 必杀技戏：强调开关、蓄力、氛围铺垫、对轰与余波
- 高潮尾戏 / 收尾戏：强调胜负之后的情绪升华与落幕

同时判断写实度：

- 高写实：注重体力消耗、距离合理性、攻击漏洞、时间差
- 中度电影化：保留因果逻辑，但允许更强的视觉夸张
- 高风格化：允许夸张位移、特效、姿态设计和节奏跳跃

如果用户没有明确要求，默认采用“中度电影化”，既保留攻防逻辑，也保留观赏性。

## Step 3: Pick The Template Combination

根据剧情需要，从下面模块里选需要的组合，不必全用：

- 开场气氛铺垫
- 开战开关 / 触发事件
- 第一轮试探性交锋
- 强弱转换 1
- 间歇 / 分开 / 游走
- 第二轮升级交锋
- 追逐或换场
- 强弱转换 2-3
- 大招前戏 / 蓄力
- 高潮对轰 / 决胜一击
- 高潮尾戏
- 收尾戏

默认目标不是“镜头越多越好”，而是让动作段落形成清晰的升级闭环。

## Step 4: Build Attack-Defense Beats

每一轮交锋都要按节拍设计，而不是只写“双方打起来了”。

至少写清：

- 谁先手，谁后手
- 攻击方式是什么：拳脚、兵器、枪械、能力、载具、环境机关
- 防御方式是什么：挡、闪、躲、借力、卸力、反制、反击
- 攻防转换的时间差在哪里
- 哪个动作暴露了漏洞
- 哪个动作造成了强弱反转

如果是近身动作戏，优先体现“见招拆招”的因果链。

如果是风格化动作戏，也至少保留“动作为什么能接上”的最小逻辑。

可优先使用“三三原则”来组织一轮交锋，例如：

- 试探
- 压制
- 反转

或：

- 进攻
- 化解
- 追击 / 反击

## Step 5: Use Space, Props, And Effects Deliberately

动作戏不能只靠人物挥动肢体。必须主动决定：

- 场地是否参与叙事：楼梯、墙面、走廊、树林、桥面、车辆、掩体
- 道具是否改变战术：桌椅、武器、碎片、绳索、门、窗、地形高差
- 位移是否改变强弱关系
- 特效是否只是装饰，还是承担叙事功能

如果环境和道具完全不影响动作过程，这场戏通常会显得平。

## Step 6: Handle Special Modules

### 对峙戏

重点不是“站着不动”，而是压迫感、心理压制和爆发前的停顿。需要写清：

- 谁先亮相
- 谁先施压
- 哪个动作或表情是开打开关
- 对峙是在积累情绪，还是在给前后动作段落留呼吸

### 追逐戏

重点不是“有人在跑”，而是方向、距离、障碍和反转。需要写清：

- 谁追谁逃
- 谁最终赢
- 中途是否反追
- 场地如何改变追逐策略
- 距离是拉开、缩短还是反复变化

### 大招 / 必杀技

必须区分：

- 大招开端：为什么必须放
- 开关：身体、武器、眼神、特效的启动信号
- 过场戏：给双方调整位置、情绪和认知的过程
- 高潮前戏：气氛蓄积、环境异变、对手反应
- 高潮戏：放出、对轰、冲击、破坏
- 放完后的输赢：谁留下、谁崩塌、谁消失、谁站立

### 高潮尾戏 / 收尾戏

高潮后不要立刻生硬结束。要区分：

- 高潮尾戏：胜负已分后的情绪升华、评价、谢幕动作
- 收尾戏：故事线收拢、状态回落、余韵与下一步钩子

## Step 7: Output Rules

严格按 `references/action-template.md` 的结构输出。

默认文件名：

- `{标题}-动作戏导演编排.md`

如果没有明确标题，可用：

- `动作戏导演编排.md`

文档必须包含：

- 场次定义
- 戏剧任务与胜负方向
- 动作风格与写实度
- 模块组合与升级路线
- 攻防节拍表
- 特殊模块设计
- 风险清单
- 下游交接建议

## Review Gate

输出后先让用户审阅，重点确认：

- 这场戏为什么打、谁赢谁输是否清楚
- 升级点和强弱反转是否足够明确
- 对峙 / 追逐 / 大招 / 尾戏是否需要增减
- 写实度和风格方向是否符合项目气质

明确提醒：

- 这是一份动作戏导演编排文档，不是最终平台提示词
- 如果通过，可交给 `continuity-blocking-planner` 细化空间衔接，或直接交给各平台分镜技能继续落地

## Quality Bar

以下情况视为失败：

- 只有“酷炫动作建议”，没有戏剧任务
- 没有强弱转换点
- 没有攻防因果或节拍设计
- 追逐戏没有方向与距离逻辑
- 大招戏没有开关、铺垫和后果
- 高潮后直接硬切结束，没有尾戏或收尾判断
- 只写视觉词，不写动作为什么成立
- 直接把导演编排写成平台 prompt
