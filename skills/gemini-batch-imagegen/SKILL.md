# Gemini 批量图片生成

用于把剧本、设定文档或分镜脚本里的图片提示词，批量送进 Gemini 网页版生成图片并下载到本地。

## 适用输入

- 一个包含可复用图片提示词的 Markdown 或纯文本文件
- 用户指定生成一张、某几个编号，或整批全部
- 用户说明要复用现有 Playwright / Chrome / Gemini 会话，或允许你新开浏览器

常见输入结构：

- 资产型：`角色 / 道具 / 场景` 小节 + 提示词代码块
- 分镜型：`分镜 N` 下包含 `Keyframe Start` 和 `Keyframe End`
- 其他变体：有稳定重复结构，但分隔符不是上面两种

## 默认约定

- 默认输出目录：`<cwd>/downloads/<markdown 文件名>/`
- 默认按原文档出现顺序处理
- 未明确筛选时，默认生成文档中全部资产
- 每张图单独一个 Gemini 对话，避免上下文串味

## 第一步：解析文档里的图片提示词

优先使用脚本抽取：

```bash
python3 .agents/skills/gemini-batch-imagegen/scripts/extract_asset_prompts.py /absolute/path/to/script.md --json
```

如果用户只要部分编号，先加 `--ids` 过滤：

```bash
python3 .agents/skills/gemini-batch-imagegen/scripts/extract_asset_prompts.py /absolute/path/to/script.md --ids C01,S14 --json
```

脚本当前优先识别两种模式：

- 资产模式：
  - 提取 `### 角色 ...` / `### 道具 ...` / `### 场景 ...`
  - 读取同一小节内第一个提示词代码块
  - 自动提取“通用画风前缀”并替换 `【通用画风前缀】`
- 分镜模式：
  - 提取每个 `分镜 N`
  - 把 `Keyframe Start` 和 `Keyframe End` 各自视为一张图
  - 合并块内的“人物形象 / 内容描述 / 风格指定”等字段作为最终提示词

脚本输出统一字段：`kind`、`id`、`title`、`prompt`、`file_stem`。

## 自动提取失败时的 fallback

不要因为脚本没命中就直接停住，也不要强行假设一种格式。

按这个顺序处理：

1. 观察文档是否有重复分隔模式
2. 推断 1-2 个最可能的分割逻辑
3. 给用户一个非常短的确认

确认内容只需要包含：

- 你打算怎么切
- 每个切块会生成什么
- 抽样展示前 1-2 个编号或标题

例如：

- `我判断这个文件应按每个“分镜”拆分，并把 Keyframe Start / End 各生成一张。先从 分镜1_START、分镜1_END 开始，确认吗？`
- `我判断这个文件应按每个三级标题下的第一个代码块拆分。先抽到 C01、P01、S14，这个分法对吗？`

只有在分割逻辑存在歧义时才需要用户确认；如果结构非常明显，可以直接继续执行。

## 第二步：建立生成队列

为每个资产准备：

- `id`
- `kind`：例如 `character` / `prop` / `scene` / `storyboard`
- 最终提示词
- 目标文件名

建议命名：

- `<id>_<file_stem>.png`
- 例如：`C01_C01-苏小月-日常形态.png`

如果用户只说“先试一张”，优先选择：

- 用户明确指定的编号
- 否则选一个最容易判读结果的场景图或 `Keyframe Start`

## 第三步：启动或复用 Gemini 会话

优先顺序：

1. 复用用户已经打开并登录的 Playwright / Chrome / Gemini 会话
2. 否则打开一个新的 headed 浏览器并进入 [Gemini](https://gemini.google.com/app)

进入 Gemini 后先检查登录状态：

- 如果页面出现“登录”按钮、账号入口缺失、或无法进入对话界面，不要继续自动化出图
- 直接让用户在已打开的浏览器窗口里手动登录
- 用户确认登录完成后，再从当前页面继续

这是强制步骤，不要假设首次访问 Gemini 时一定已登录。

## 第四步：为每张图片执行固定流程

每张图都走同一套流程：

1. 打开 Gemini 新对话
2. 确认模式为 `Pro`
3. 打开 `制作图片` 工具
4. 将最终提示词粘贴到输入框
5. 发送并等待生成完成
6. 确认本次生成链路里出现 `Nano Banana 2`
7. 点击“下载完整尺寸的图片”
8. 把下载文件复制到目标输出目录

## 提示词处理规则

- 以文档中的原始提示词为主，不重写设定
- 仅在必要时追加很短的约束，避免模型偏题
- 常用补充约束：
  - `不要文字，不要水印，不要 logo`
  - 人物 / 道具图：`保持纯白背景，不添加环境`
  - 场景图：`不要加入未提及的人物`
- 如果原提示词已经包含这些限制，不要重复堆叠

对分镜型文档：

- `Keyframe Start` 和 `Keyframe End` 分开生成，不要混成一张图
- 除非用户明确要求，否则不要改写人物锚点和风格锚点
- 如果文档已经内置了风格字段，不要再额外塞一大段重复画风

## 下载与落盘

下载后必须做两件事：

1. 从 Playwright 返回的下载事件里确认临时文件路径
2. 复制到目标目录，并用资产编号命名

推荐同时生成一个简单清单文件，例如 `manifest.md`，记录：

- 源 Markdown 路径
- 生成时间
- 每个资产的 `id`
- 对应保存路径
- 是否首次成功，或是否重生过

## 批量执行建议

- 长队列时，每生成 1 张就立刻下载和落盘
- 每张图尽量单独对话，避免 Gemini 把上一张图的内容带到下一张
- 如遇速率限制、排队或生成失败，暂停几秒后重试当前项，不要直接跳过
- 如遇明显文字、水印、背景错误，先加强负面约束再重生一次

## 结束前检查

交付前至少确认：

- 目标目录存在
- 预期文件确实已落盘
- 抽样预览 1-2 张关键图片，确认不是空文件或错误下载
- 如果有失败项，明确列出未完成的编号

## 输出给用户时要说明

- 用的是哪个 Markdown 文件
- 生成了哪些编号
- 文件保存到哪里
- 如果有需要人工继续的地方，例如 Gemini 登录、失败重试、质量问题
