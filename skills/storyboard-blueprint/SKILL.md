# 导演分镜蓝图

## Overview

把故事或剧本先整理成一份“导演能审、团队能对齐、下游技能能接”的平台无关蓝图文档。

核心原则：先做导演层判断，再做平台层翻译。默认输出的是导演分镜蓝图，不是 Seedance / Hailuo / Wanxiang / Vidu 的最终提示词。

生成前先阅读：
- `references/blueprint-template.md`：固定输出结构与字段要求
- `references/analysis-checklist.md`：导演讲戏提取、5W2H 审查、风险扫描清单

## Scope Decision

先判断这次蓝图应该覆盖什么单位：

1. 用户给的是整季或多集大纲：
只蓝图当前要处理的一集，或按集拆开分别输出。

2. 用户给的是单集内多场戏：
按场次拆分，但保持一份文档内的主次关系。

3. 用户给的是单场戏或单段剧情：
直接围绕这一段做蓝图。

4. 用户只有模糊创意，没有可落地剧情：
不要硬做蓝图，先建议使用 `story-creator` 或先补剧情文本。

如果输入跨越多个彼此独立的戏份，先缩小范围，不要把互不相干的段落揉成一份蓝图。

## Workflow Overview

按下面顺序执行：

1. 判断范围与单位
2. 提取导演讲戏信息
3. 分析三段幕、权重节奏与重点戏
4. 提炼主情绪与强弱转换点
5. 运行 5W2H 信息完整度审查
6. 提出至少 2 个镜头组装方向并给出推荐
7. 生成平台无关的镜头段落蓝图
8. 标记连续性、资产与理解风险
9. 保存 Markdown 文档并要求人审

## Step 1: Build The Working Context

先从输入里提取这些基础信息：

- 当前处理单位：整集 / 场次 / 单段剧情
- 作品标题或临时标题
- 类型与风格
- 目标时长或大致篇幅
- 已知角色
- 已知场景
- 当前已有资产：角色图、场设、VDD、参考片、已有分镜

如果信息缺失，不要立刻停住。先用现有内容往下做，并在文档里显式记录假设与缺口。

## Step 2: Extract Director-Lecture Information

把输入当成一次“导演讲戏”来听，先归纳这几个判断：

- 这段内容在整集里的作用与定位
- 这是不是重点戏，重点等级如何
- 哪些地方必须重刻画
- 哪些地方只能服务主线，不能抢戏
- 导演或用户明确偏好的审美、运镜、节奏、参考来源
- 创作边界：哪些能改，哪些不能改

如果用户没有明确说出这些信息，也要基于剧情主动推断，并把推断写清楚。

## Step 3: Analyze Weight, Structure, And Emotional Beats

先按三段幕或更适合的局部结构拆解：

- 开端
- 过程
- 结局

然后判断：

- 哪一段是真正重点
- 哪些内容应该压缩
- 哪些内容值得重复铺垫
- 情绪主线是什么
- 每个阶段的情绪名词是什么
- 强弱转换点出现在哪里

强弱转换点必须写成可执行判断，而不是空泛描述。要明确：

- 谁更强，谁更弱
- 转换由什么动作、信息或环境变化触发
- 转换前后观众感受如何变化
- 这个点值不值得单独加镜头强化

## Step 4: Run 5W2H Completeness Audit

逐段、逐镜头组检查：

- `Who`：谁在场，主次关系是什么
- `What`：当前到底发生了什么
- `Why`：这个行为或镜头存在的理由是什么
- `When`：时间状态是否清楚
- `Where`：空间位置与地形是否清楚
- `How`：动作、衔接、推进方式是否可拍可写
- `How many`：人数、道具数量、敌我规模是否清楚

如果某一项回答不清，就在文档里标记为“信息缺口”或“资产缺口”，而不是假装问题不存在。

## Step 5: Propose Assembly Directions

至少给出 2 个可行的镜头组装方向，再推荐其中 1 个。

常见方向包括但不限于：

- 先建场再入戏
- 从局部碎切直接入戏
- 先交代强者状态
- 先交代弱者反应
- 先环境后人物
- 先动作后空间

每个方向都要说明：

- 适合强调什么
- 优点是什么
- 缺点是什么
- 对节奏和资源的影响是什么

推荐时必须给出理由，不要只说“更好”。

## Step 6: Build A Platform-Agnostic Shot Blueprint

蓝图默认按“镜头段落”或“镜头组”组织，而不是直接写平台提示词。

每个镜头段落至少包含：

- 段落编号与名称
- 戏剧目标
- 必须交代的信息
- 目标情绪
- 强弱状态与是否含转换点
- 建议镜头数量范围
- 建议景别范围
- 建议机位或视角
- 建议运镜倾向
- 建议衔接方式
- 推荐插入的空镜 / 物件 / 锚点镜头
- 建议强化的环境、光影、动作或表情元素
- 可压缩项与不可删项

必要时可以补“候选微镜头”，但保持平台无关。不要写成任何具体平台的语法，不要使用 `@素材`、生成参数或泛化风格尾缀。

## Step 7: Scan Risks Before Handoff

在文档末尾必须专门标记风险，至少检查：

- 是否存在越轴风险
- 站位和走位是否可能看不懂
- 是否缺少锚定镜头
- 情绪是否有断裂
- 是否存在剧情重点与镜头时长不匹配
- 是否有地形、道具、角色数量不清导致的返工风险
- 是否已经提前暴露出“画得太平”或“看不懂”的问题

如果发现风险，要给出缓解建议，而不是只报问题。

## Output Rules

严格按 `references/blueprint-template.md` 的结构输出。

默认文件名：

- `{标题}-导演分镜蓝图.md`

如果没有明确标题，可用：

- `导演分镜蓝图.md`

文档必须满足以下要求：

- 能让人类先审阅并讨论
- 能让下游技能看懂结构意图
- 明确区分“必须信息”和“可发挥空间”
- 不直接写成平台提示词
- 不跳过取舍理由

## Review Gate

输出蓝图后，先让用户审阅。

明确提醒：

- 这是一份导演层蓝图，不是最终平台提示词
- 如需进一步落地，可进入 `continuity-blocking-planner`
- 如果已经足够明确，也可直接交给 `seedance-storyboard`、`hailuo-storyboard`、`wanxiang-storyboard`、`vidu-storyboard`

默认先问用户是否要修改蓝图，再进入下游翻译阶段。

## Quality Bar

以下情况视为失败：

- 只复述剧情，没有导演判断
- 没有权重节奏和重点戏判断
- 没有强弱转换点
- 没有 5W2H 缺口审查
- 没有至少 2 个组装方向
- 直接越级写成平台提示词
- 没有风险提示与下游交接建议
