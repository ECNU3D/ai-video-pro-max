# 视频生成预检查系统

## 概述

在将素材提交到 AI 视频平台（Seedance/Hailuo/Wanxiang/Vidu）生成之前，系统化审查**首帧参考图、可选尾帧参考图与提示词**之间的一致性，提前发现问题，避免浪费生成成本。

**核心理念：生成一次视频的成本不低。与其生成后发现问题重来，不如生成前把问题拦住。**

## 输入

| 输入 | 必需 | 说明 |
|------|------|------|
| 首帧参考图 | 是 | 将喂给视频平台的首帧图片 |
| 提示词文本 | 是 | 将提交给视频平台的完整提示词 |
| 尾帧参考图 | 否 | 如使用首尾帧模式，提供尾帧图片 |
| 角色设定图 | 否 | 角色锚定参考（用于检查角色一致性） |
| 视觉设计文档(VDD) | 否 | 用于检查色彩/风格是否符合整体设计 |
| 目标平台 | 否 | Seedance/Hailuo/Wanxiang/Vidu（影响提示词规范检查） |

## 模式自动检测

- 提供首帧 + 提示词 → **首帧模式**（start_only）
- 提供首帧 + 尾帧 + 提示词 → **首尾帧模式**（start_end）

## 工作流程

### 第一步：读取所有输入

1. 读取首帧图片，观察并记录：主体身份、姿态、表情、服装道具、构图机位、光线色温、场景环境、画风
2. 如有尾帧，同样观察记录
3. 读取提示词文本

### 第二步：结构化解析提示词

将提示词强制拆解为以下结构（如果提示词中某项缺失，明确标注"未指定"）：

```
主体：[谁/什么]
初始状态：
  - 姿态：
  - 表情：
  - 构图/机位：
  - 场景环境：
目标状态：
  - 姿态：
  - 表情：
  - 构图/机位：
  - 场景环境：
要求发生的变化：
  - [变化1]
  - [变化2]
运镜指令：[推/拉/摇/跟/固定/环绕...]
禁止发生的变化：
  - [如有]
节奏/时序线索：
  - [如有，如"0-3秒...3-6秒..."]
风格约束：
  - [如有]
模糊/缺失项：
  - [列出提示词中不够明确的部分]
```

### 第三步：逐维度审查

按 `references/audit-criteria.md` 中的标准逐维度检查。

#### 维度 1：首帧-提示词一致性（权重见评分表）

逐项对比首帧画面与提示词解析出的「初始状态」：

| 检查项 | 对比内容 |
|--------|---------|
| 主体身份 | 首帧中的人物/物体是否与提示词描述一致 |
| 姿态动作 | 首帧中的姿势是否匹配提示词的初始姿态 |
| 服装道具 | 首帧中的穿着和持有物是否一致 |
| 构图机位 | 首帧的景别和角度是否匹配提示词的镜头描述 |
| 场景环境 | 首帧的背景、场景是否匹配 |
| 光线色温 | 首帧的光线条件是否与提示词描述一致 |
| 画风风格 | 首帧的艺术风格是否与提示词要求一致 |

**关键原则**：不要说"大体一致"——必须指出具体哪些一致、哪些不一致。

#### 维度 2：尾帧-提示词一致性（仅首尾帧模式）

同维度1，但对比尾帧画面与提示词解析出的「目标状态」。

额外检查：
- 提示词要求到达的终态是否在尾帧中已经体现
- 如果提示词的目标状态与尾帧画面矛盾，必须标记冲突

#### 维度 3：首尾帧一致性（仅首尾帧模式）

首帧到尾帧之间是否存在不合理的跳变：

| 检查项 | 说明 |
|--------|------|
| 角色身份 | 是否同一个人/物，面部特征是否一致 |
| 服装道具 | 除非提示词要求换装，否则应保持一致 |
| 场景环境 | 除非提示词要求切场景，否则背景应连贯 |
| 画风一致 | 两帧的艺术风格/色调是否统一 |
| 变化合理性 | 从首帧到尾帧的变化在4-15秒内是否物理可行 |

#### 维度 4：迁移逻辑完整性

检查提示词是否清晰定义了从初始状态到目标状态的变化路径：

| 检查项 | 说明 |
|--------|------|
| 变化是否明确 | 提示词是否清楚说明了需要发生什么变化 |
| 变化是否可行 | 在目标时长内，这些变化是否物理上合理 |
| 顺序是否清晰 | 如有多个变化，先后顺序是否明确 |
| 禁止项是否明确 | 不该发生的变化是否已声明（如"不换场景""不跳切"） |
| 运镜是否匹配 | 运镜指令是否与变化内容协调 |
| 首尾帧差距可达 | 从首帧到尾帧的视觉变化量是否在合理范围（差距过大=风险高） |

#### 维度 5：提示词质量

| 检查项 | 说明 |
|--------|------|
| 结构完整性 | 是否包含：运镜 + 主体 + 场景 + 动作 + 风格 |
| 时序节点 | 是否使用时间节点（0-3秒 / 3-6秒...）拆分动作 |
| 关键词准确性 | 运镜/风格关键词是否为目标平台的有效词汇 |
| 冗余/矛盾 | 提示词内部是否有自相矛盾的描述 |
| 平台适配 | 提示词长度、格式是否适合目标平台 |
| 缺失元素 | 是否遗漏关键信息（如光线、表情变化、运镜方向） |

### 第四步：评分与判定

#### 首帧模式评分权重

| 维度 | 权重 |
|------|------|
| 首帧-提示词一致性 | 35 |
| 迁移逻辑完整性 | 40 |
| 提示词质量 | 25 |
| **合计** | **100** |

#### 首尾帧模式评分权重

| 维度 | 权重 |
|------|------|
| 首帧-提示词一致性 | 20 |
| 尾帧-提示词一致性 | 20 |
| 首尾帧一致性 | 15 |
| 迁移逻辑完整性 | 25 |
| 提示词质量 | 20 |
| **合计** | **100** |

#### 判定标准

| 等级 | 分数 | 判定 | 行动 |
|------|------|------|------|
| A | 85-100 | 通过 | 可以提交生成 |
| B | 70-84 | 基本可用 | 建议修改后再生成 |
| C | <70 | 不通过 | 必须修改，当前提交大概率浪费生成次数 |

#### 一票否决（直接判定不通过）

无论总分多高，出现以下任一情况直接标记为「不通过」：

1. 首帧中的人物与提示词描述的主体明显不同
2. 尾帧与提示词目标状态严重矛盾
3. 首尾帧之间角色身份不一致（非提示词要求的变化）
4. 提示词中关键变化缺失（既没描述要发生什么，也没描述目标状态）
5. 首尾帧差距过大，在目标时长内物理不可行

## 核心原则

1. **具体不含糊** — 不说"大体一致"，必须逐项指出具体的一致和不一致之处
2. **证据先行** — 每个判断都要指向首帧/尾帧/提示词中的具体内容
3. **可操作** — 所有问题都附带具体修改建议，最好直接给出修改后的提示词
4. **宁严勿松** — 生成成本不低，宁可多拦一次也不要放过问题
5. **分清失败类型** — 明确区分：帧词不匹配 / 迁移逻辑缺陷 / 首尾帧不一致 / 提示词质量问题
6. **置信度诚实** — 如果提示词模糊导致无法确定判断，降低置信度并说明原因
